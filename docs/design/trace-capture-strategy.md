## Duplication, portability, evidence limits

The recorder's Rust integration tests exercise current-server mechanics; historical sidecar consistency checks do not. Do not weaken recorder coverage into a generic parser test, but do not preserve hundreds of historical assertions merely to keep their fixtures alive. The reconstructed-JSONL parse is also redundant: it neither drives fake editor nor server. Reuse `ui_lib.driver` where it supports a required native action; retain VSCode's own launcher and Helix as manual smoke only, not a new supported harness (AGENTS.md). Reproducibility means equivalent behavior and checked editor/server state, not identical PIDs, timestamps or temporary paths.

The trace README records unavailable `/tmp/opencode` source paths and missing exact launch/cleanup commands for some captures. These paths are historical provenance, not runtime dependencies. Embedded recipes using `/tmp/opencode` paths, installed editor binaries, shell process tools or editor-version assumptions are machine-specific; make future capture destinations temporary/repository-independent and report prerequisites explicitly. Current Linux-only evidence does not establish Windows/macOS execution; retain CI follow-ups and make no cross-platform claim. No builds, tests, native captures, or recapture were run for this audit.

## Ordered cleanup slices

1. **Remove historical-only gates:** inventory remaining consumers, remove the reconstructed parse-only check and heavily reduce bespoke sidecar assertions. Any unique regression must exercise existing fake-editor/server infrastructure, not another comparison between static files. Keep recorder product tests and active quirk/declaration inputs.
2. **Prune fixture duplication:** retain one canonical input per live need, small generic integrity checks and compact provenance. Remove action sidecars, duplicate representations and captures without live consumers; cite immutable Git history instead of maintaining dead evidence machinery.
3. **Retire or consolidate capture programs:** delete Markdown-embedded programs and stale temporary-driver instructions. Extract only workflows justified by ongoing native evidence/regeneration needs, reusing maintained launchers and shared lifecycle ownership; avoid a new Helix harness or a separate utility for each historical action.
4. **Make retained tools reproducible:** use explicit arguments, repository-relative discovery and standard temporary directories; remove hard-coded host paths, `/proc` dependencies and bespoke platform process handling. Test extraction/validation logic portably, use existing native adapters where required, and state Linux-only evidence/other-platform CI limits. Keep source edits, test execution and artifact ownership separate from historical provenance.

These are implementation decisions, not permission to weaken production coverage. Each slice must identify removed consumers and preserve meaningful regressions; historical effort alone is not a retention criterion. This audit implements no cleanup and revalidates no native behavior.
